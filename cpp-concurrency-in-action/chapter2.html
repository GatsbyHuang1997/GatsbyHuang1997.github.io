Chapter 2: Managing threads

Basic thread management

Launching a thread

Use std::thread to start a new thread of execution. Pass a callable (function, lambda, functor) to the constructor:

void doWork() {
  // background task
}

std::thread t(doWork);
t.join();

The thread begins executing immediately upon construction. You must decide whether to join() (wait for completion) or detach() (let it run independently) before the std::thread object is destroyed.

Passing a callable object

Instead of a free function, you can pass a class with an overloaded operator():

class BackgroundTask {
 public:
  void operator()() const {
    // do something in background
  }
};

BackgroundTask task;
std::thread myThread(task);
myThread.join();

Mind the Most Vexing Parse

std::thread myThread(BackgroundTask()) is parsed as a function declaration — a function named myThread taking a pointer to a function returning BackgroundTask. Use extra parentheses or brace initialization:

std::thread myThread((BackgroundTask())); // extra parentheses
std::thread myThread{BackgroundTask{}};   // brace initialization

Using lambdas

Lambdas are often the most convenient way to launch a thread — no separate function or class needed:

std::thread t([]() {
  // do work inline
});
t.join();

Capture local variables to pass data without relying on std::ref:

int factor = 10;
std::thread t([factor]() {
  int result = factor * 2;
  // process result
});
t.join();

Capture by reference to avoid copies, but ensure the referenced variables outlive the thread:

int sum = 0;
std::thread t([&sum]() {
  for (int i = 0; i < 100; ++i) {
    sum += i;
  }
});
t.join();
// sum is now 4950

Capturing by reference

Just like std::ref, capturing by reference with a detached thread leads to dangling references if the referenced variable goes out of scope. Prefer capturing by value or joining the thread before the variable is destroyed.

join vs detach

  • join() — Blocks the calling thread until the joined thread finishes. Each thread must be joined or detached exactly once.
  • detach() — Separates the thread from the std::thread object. The thread runs independently and cannot be joined afterward. Use with caution — detached threads are hard to manage (no easy way to check completion, pass results, or ensure they finish before process exit).

Always call joinable() before join() or detach() to avoid std::system_error.

RAII and exception safety

If an exception is thrown before join(), the thread is left unjoined and std::terminate is called in the destructor. Wrap threads in an RAII class to guarantee cleanup:

class ThreadGuard {
  std::thread& t;

 public:
  explicit ThreadGuard(std::thread& t_) : t(t_) {}
  ~ThreadGuard() {
    if (t.joinable()) t.join();
  }
  ThreadGuard(const ThreadGuard&) = delete;
  ThreadGuard& operator=(const ThreadGuard&) = delete;
};

void doWork() { /* ... */ }

std::thread t(doWork);
ThreadGuard g(t);
// if an exception is thrown here, ~ThreadGuard joins t

Passing arguments to a thread

Arguments are passed by value by default — copied/moved into the thread's internal storage before invocation.

Passing by reference with std::ref

The thread constructor does not auto-deduce references. Wrap with std::ref (or std::cref for const) to pass by reference:

void processData(int& data);
int value = 42;
std::thread t(processData, std::ref(value));

Passing member functions

The first argument must be the object to call on:

class Worker {
 public:
  void doWork(int count) { /* ... */ }
};

Worker w;
std::thread t(&Worker::doWork, &w, 10);

Move semantics

std::thread passes arguments via std::move, so movable-only types can be transferred:

void processPtr(std::unique_ptr<int> ptr);
std::thread t(processPtr, std::unique_ptr<int>(new int(42)));

Beware of implicit conversions

Arguments are stored with decayed types, which can cause surprising behavior:

void f(int x);
std::thread t(f, "hello"); // compiles, but x receives garbage pointer value

The string literal "hello" decays to const char* and is stored internally. When f is invoked, the const char* is implicitly converted to int — undefined behavior. Always ensure the type you pass matches the expected parameter type.

Transferring thread ownership

std::thread is move-only — it cannot be copied. Use std::move to transfer ownership:

std::thread t1(doWork);
std::thread t2(std::move(t1)); // t1 is now empty, t2 owns the thread

t2.join();

This is useful for returning threads from functions or storing them in containers:

std::thread createThread() {
  return std::thread(doWork); // moved via RVO
}

std::vector<std::thread> threads;
threads.push_back(std::thread(doWork)); // moved into vector
threads.emplace_back(doWork);            // constructs in place

C++20: std::jthread

std::jthread provides built-in RAII — its destructor automatically calls join() if the thread is still joinable:

#include <thread>

void doWork(int count) { /* ... */ }

std::jthread jt(doWork, 42); // destructor joins automatically

Key differences from std::thread:

  • Auto-join on destruction — no RAII wrappers needed.
  • Cooperative cancellation — accepts a std::stop_token as the first argument. Call jt.request_stop() from another thread to signal cancellation:
void cancellableWork(std::stop_token stoken) {
  while (!stoken.stop_requested()) {
    // do work
  }
}

std::jthread jt(cancellableWork);
jt.request_stop(); // destructor joins after stop
  • No default constructor — must be given a callable at construction.

Implementation

A simplified implementation showing the core idea — destructor joins, and std::stop_token is conditionally passed if the callable accepts it:

// Simplified implementation of std::jthread (C++20)
class jthread {
 public:
  // No default constructor — must provide a callable
  jthread() = delete;

  template <typename F, typename... Args>
  explicit jthread(F&& f, Args&&... args)
      : stop_source_(std::make_shared<std::stop_source>()),
        thread_([f = std::forward<F>(f),
                 args = std::make_tuple(std::forward<Args>(args)...),
                 stop_source = stop_source_]() mutable {
          std::apply(
              [&f, &stop_source](auto&&... a) {
                if constexpr (requires { f(stop_source.get_token(), a...); }) {
                  f(stop_source.get_token(), std::forward<decltype(a)>(a)...);
                } else {
                  f(std::forward<decltype(a)>(a)...);
                }
              },
              std::move(args));
        }) {}

  ~jthread() {
    if (thread_.joinable()) {
      request_stop();
      thread_.join();
    }
  }

  // Move-only
  jthread(jthread&&) noexcept = default;
  jthread& operator=(jthread&&) noexcept = default;
  jthread(const jthread&) = delete;
  jthread& operator=(const jthread&) = delete;

  void request_stop() { stop_source_->request_stop(); }

  bool joinable() const noexcept { return thread_.joinable(); }
  void join() { thread_.join(); }
  void detach() { thread_.detach(); }
  std::thread::id get_id() const noexcept { return thread_.get_id(); }

 private:
  std::shared_ptr<std::stop_source> stop_source_;
  std::thread thread_;
};

Key implementation details:

  • The constructor uses a variadic template to forward arguments to the callable.
  • std::apply unpacks the tuple of arguments when invoking the callable.
  • if constexpr (requires {...}) detects at compile time whether the callable accepts a std::stop_token — if so, it is passed as the first argument; otherwise, the callable is invoked without it.
  • The destructor calls request_stop() then join(), ensuring the thread always finishes cleanly.

Choosing the number of threads at runtime

std::thread::hardware_concurrency() returns the number of concurrent threads supported by the hardware (e.g., number of CPU cores). Use this to avoid over-subscription — launching significantly more threads than cores can hurt performance due to context-switching overhead.

The return value is implementation-defined: it may return the exact core count, or 0 if the value cannot be determined.

unsigned int numThreads = std::thread::hardware_concurrency();
if (numThreads == 0) {
  numThreads = 2;  // fallback when the value is unknown
}

std::vector<std::thread> threads;
for (unsigned int i = 0; i < numThreads; ++i) {
  threads.emplace_back(doWork, i);
}

for (auto& t : threads) {
  t.join();
}

This is particularly useful when splitting work across a thread pool or parallelizing data processing — aim for one thread per core for CPU-bound tasks, and more threads for I/O-bound tasks where threads spend time waiting.

Related queries

C++17 also provides two additional hardware queries:

  • std::thread::hardware_concurrency() — number of concurrent threads (logical cores).
  • std::thread::hardware_destructive_interference_size — minimum offset between two objects to avoid false sharing (in bytes). Typically the size of a cache line (e.g., 64 bytes).
  • std::thread::constructive_interference_size — maximum size for two objects to share a cache line (in bytes). Typically also 64 bytes.

Avoiding false sharing

When multiple threads frequently write to independent variables that happen to reside on the same cache line, the CPU must constantly synchronize cache coherence — a phenomenon called false sharing. Use std::hardware_destructive_interference_size to pad data so each thread works on a separate cache line:

struct PaddedCounter {
  alignas(std::hardware_destructive_interference_size) std::atomic<int> count;
};

PaddedCounter counters[4];
// each counter is on its own cache line — no false sharing between threads

Both hardware_destructive_interference_size and constructive_interference_size may return 0 when the value is unknown, in which case you should fall back to a sensible default (typically 64).

Guidelines for choosing thread count

Workload typeSuggested thread count
CPU-bound (pure computation)hardware_concurrency()
I/O-bound (network, disk)hardware_concurrency() * 2 or higher, based on expected wait ratio
Mixed (CPU + I/O)Use a thread pool with hardware_concurrency() workers and async I/O

The key principle: if threads spend more time waiting than computing, you can safely run more threads than cores. If threads are fully CPU-bound, running more threads than cores will degrade performance due to context-switching overhead.

Identifying threads

Every thread has a unique ID of type std::thread::id. You can obtain it from inside the thread via std::this_thread::get_id(), or from outside via t.get_id() on the owning std::thread object.

An empty/default-constructed std::thread returns a default-constructed std::thread::id — this can be used to check whether a thread object is valid:

std::thread t;
std::cout << std::boolalpha << (t.get_id() == std::thread::id()) << "\n";
// prints: true — no thread is associated

std::thread::id is copyable and comparable, making it useful as a key in maps or for logging:

std::map<std::thread::id, int> threadData;
threadData[std::this_thread::get_id()] = 42;

It can also be used to determine whether the current thread is the one executing a given piece of work:

void criticalSection() {
  if (std::this_thread::get_id() == expectedThreadId) {
    // already on the expected thread — no synchronization needed
  } else {
    // need to synchronize
  }
}

Thread ID as a logging tag

std::thread::id is streamable via operator<<, so it integrates naturally with logging frameworks:

std::cout << "Running on thread " << std::this_thread::get_id() << "\n";

The actual value of the ID is implementation-defined — it may be a number, a pointer, or some opaque identifier. Never rely on its internal representation; only use it for comparison and identification.

Data safety — avoiding dangling references

When passing arguments by reference, ensure the referenced object outlives the thread:

void updateData(int& data) {
    // modifies data
}

void oops() {
    int someLocalData = 0;
    std::thread t(updateData, std::ref(someLocalData));
    t.detach(); // don't wait
} // someLocalData is destroyed, but t may still be running — undefined behavior

Use join(), pass by value, or transfer ownership of the data to the thread to avoid this.
